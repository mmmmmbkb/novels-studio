# 📖 استوديو الروايات — Novels Studio

تطبيق ويب مستقل وكامل لكتابة الروايات، مرتبط بمجموعة **MIRAX NOVELS - ميراكس للروايات** على فيسبوك
(خاصة، ~70,000 عضو، ID: `918194596679289`).

كل كاتب له **حساب خاص** (إيميل + كلمة مرور، أو فيسبوك)، ورواياته وفصوله ونقاطه محفوظة باسمه
ومنفصلة تمامًا عن باقي المستخدمين. الدخول للاستوديو بعد **التحقق من عضوية الجروب** وموافقة الأدمن.

> **اقرأ هذا أولًا — حدود فيسبوك الحقيقية (موثقة):**
> ألغت Meta واجهة **Facebook Groups API بالكامل في 22 أبريل 2024** (Graph API v19.0)، ومعها
> الصلاحيتين `publish_to_groups` و`groups_access_member_info`، ولم يعد بإمكان أدمن الجروب تثبيت
> أي تطبيق داخل الجروب. هذا يعني:
>
> | ما كان مطلوبًا | الواقع بعد 2024 |
> |---|---|
> | تحقق تلقائي من عضوية مستخدم في الجروب عبر API | ❌ **مستحيل** — لا يوجد endpoint رسمي يقرأ قائمة الأعضاء |
> | نشر تلقائي في الجروب عبر API | ❌ **مستحيل** — لا يوجد endpoint رسمي ينشر في جروب |
> | تسجيل دخول بفيسبوك لإثبات الهوية (`public_profile` + `email`) | ✅ يعمل عبر Supabase Auth / Facebook Login |
> | ربط بروفايل فيسبوك + طلب تحقق يوافق عليه الأدمن يدويًا | ✅ **هذا هو الحل المنفذ في هذا المشروع** |
> | تجهيز منشور منسق + نسخه + فتح الجروب والنشر يدويًا | ✅ منفذ في `/api/publish` + واجهة الاستوديو |
>
> أي مشروع أو أداة تدّعي اليوم تحققًا تلقائيًا كاملًا من عضوية جروب فيسبوك أو نشرًا آليًا فيه
> عبر API رسمي فهي **غير صادقة أو تستخدم طرقًا مخالفة لشروط فيسبوك** — هذا المشروع لا يفعل ذلك.

## ✨ المميزات

- **حسابات متعددة حقيقية:** تسجيل بالإيميل + كلمة مرور عبر Supabase Auth، وتسجيل دخول بفيسبوك (Facebook Login) عند ضبطه. أول مستخدم مسجَّل — أو الإيميل في `NEXT_PUBLIC_ADMIN_EMAIL` — يصبح أدمن.
- **التحقق من العضوية:** المستخدم يربط رابط بروفايل فيسبوك + ملاحظة → طلب `pending` → الأدمن يراجع من **لوحة التحكم `/admin`** (يفتح البروفايل ويتأكد من العضوية في الجروب على فيسبوك) → موافقة/رفض. لا يُفتح الاستوديو قبل الموافقة (الأدمن مستثنى).
- **مكتبة روايات:** إنشاء روايات، أغلفة ملوّنة أو **رفع صورة غلاف من الجهاز** (JPG/PNG/WebP حتى 8MB — تُرفع إلى Supabase Storage bucket `covers` في الوضع الحقيقي، أو تُحفظ Data URL في الوضع المحلي).
- **محرر فصول احترافي:** خط عربي مريح، عدّاد كلمات حي، حفظ، نقاط كلمات تلقائية.
- **تصدير PDF:** تصدير الرواية كاملة (غلاف + فصول مرتبة) عبر نافذة طباعة → Save as PDF.
- **النشر في الجروب:** تجهيز نص منسق → نسخ → فتح الجروب → النشر يدويًا من حسابك → تأكيد النشر (مع رابط المنشور اختياريًا) → **+50 نقطة**.
- **نظام نقاط ومستويات:** نشر +50 · فصل جديد +10 · +5 لكل 500 كلمة · +2 لكل تفاعل · +5 لكل تعليق (مزامنة يدوية من المنشور، تُحتسب الزيادة فقط) · مستويات من «كاتب مبتدئ» إلى «أسطورة ميراكس» · **لوحة متصدرين `/leaderboard`**.
- **واجهة عربية RTL** كاملة.

## 🗄️ قاعدة البيانات — لماذا Supabase؟

قارنّا البدائل المجانية (الأرقام من صفحات الأسعار الرسمية، نوفمبر 2026 — تحقق منها قبل الاعتماد عليها):

| | **Supabase ✅ (المختار)** | Firebase (Spark) | Appwrite Cloud (Free) |
|---|---|---|---|
| قاعدة البيانات | **Postgres حقيقي 500MB**، SQL + RLS | Firestore NoSQL 1GiB (50K قراءة/يوم، 20K كتابة/يوم) | TablesDB، 2GB تخزين |
| المصادقة | 50,000 MAU، إيميل + OAuth (فيسبوك) | 50,000 MAU | **75,000 MAU** |
| التخزين | 1GB ملفات | 5GB | 2GB |
| خروج البيانات | 5GB/شهر | 10GB/شهر | 5GB/شهر |
| كود سيرفر مجاني | Edge Functions 500K استدعاء/شهر | ❌ Cloud Functions تحتاج Blaze (مدفوع) | 750K تنفيذ |
| مفتوح المصدر / نقل | ✅ Apache-2.0، استضافة ذاتية ممكنة | ❌ مغلق | ✅ BSD، استضافة ذاتية |
| المشاريع المجانية | 2 مشروع | غير محدود تقريبًا | 2 مشروع |
| **أهم قيد** | **يتوقف بعد أسبوع خمول**، لا نسخ احتياطي تلقائي في المجاني، إيميلات Auth بلا SMTP مخصص: 2/ساعة | Firestore ليست علائقية؛ Postgres عبر SQL Connect يبدأ ~$9.37/شهر | يتجمد عند بلوغ الحد؛ SQL أقل نضجًا من Postgres |

**الاختيار: Supabase** — لأنه الوحيد الذي يعطي Postgres علائقية حقيقية + Auth + Storage + دوال سيرفر
في باقة مجانية واحدة، مع RLS يفصل بيانات كل مستخدم على مستوى قاعدة البيانات نفسها،
وهو الأنسب تمامًا لعلاقات (مستخدم ← روايات ← فصول ← نقاط) في هذا المشروع.
Appwrite أقرب منافس (MAU أعلى)، وFirebase أفضل لو كان التطبيق موبايل أصليًا بالكامل — لكنهما
لا يضيفان شيئًا لهذا المشروع يبرر التخلي عن Postgres.

**حدود الباقة المجانية التي يجب أن تعرفها:**
- المشروع **يتوقف (Pause) بعد أسبوع من عدم النشاط** — أعد تفعيله من لوحة Supabase بضغطة واحدة.
- 500MB قاعدة بيانات، 1GB تخزين، 5GB خروج/شهر، 50K مستخدم نشط/شهر — كافية لآلاف الكتّاب في البداية.
- بلا SMTP مخصص، إيميلات تأكيد التسجيل محدودة بـ 2/ساعة — اضبط SMTP خاصًا (SendGrid/SES) عند الإطلاق العام، أو أوقف تأكيد الإيميل من إعدادات Auth مؤقتًا.
- الترقية عند الحاجة: Pro من $25/شهر (8GB قاعدة بيانات، 100GB تخزين).

**الوضع المحلي (بدون Supabase):** يعمل التطبيق فورًا بحسابات منفصلة محفوظة في `localStorage`
على جهاز المستخدم — للتجربة والتطوير فقط. **الوضع الحقيقي** يبدأ تلقائيًا عند ضبط
`NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

## 🚀 النشر على Vercel — خطوة بخطوة

### 1) ارفع المشروع إلى GitHub
```bash
cd novels-studio
git init && git add . && git commit -m "Novels Studio v1"
git remote add origin https://github.com/YOUR-USERNAME/novels-studio.git
git push -u origin main
```

### 2) أنشئ مشروع Supabase (مجاني)
1. https://supabase.com/dashboard → New project → احفظ كلمة مرور قاعدة البيانات.
2. **SQL Editor** → الصق محتوى `supabase/migrations/001_init.sql` كاملًا → Run.
3. **Storage** → New bucket باسم `covers` → اجعله **Public**.
4. **Settings → API**: انسخ `Project URL` و `anon public key` و `service_role key`.
5. (اختياري، للفيسبوك) **Authentication → Providers → Facebook**: فعّله بعد الخطوة 4 أدناه.
6. (موصى به) **Authentication → SMTP Settings**: اضبط SMTP خاصًا لتجاوز حد 2 إيميل/ساعة.

### 3) انشر على Vercel
[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/YOUR-USERNAME/novels-studio)
أو يدويًا:
1. https://vercel.com/new → Import من GitHub → اختر `novels-studio`.
2. Framework: **Next.js** (يُكتشف تلقائيًا).
3. **Environment Variables** — أضف من `.env.example`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (سري — بلا بادئة `NEXT_PUBLIC_`)
   - `NEXT_PUBLIC_ADMIN_EMAIL` = إيميل محمود (الأدمن)
   - `NEXT_PUBLIC_GROUP_ID=918194596679289`
   - `NEXT_PUBLIC_GROUP_URL=https://www.facebook.com/groups/918194596679289/`
4. **Deploy**. جرّب: `/api/health` ثم أنشئ حسابك (ستصبح أدمن تلقائيًا إن كان إيميلك هو `NEXT_PUBLIC_ADMIN_EMAIL`).

> ⚠️ **لا تنشر أبدًا بدون متغيرات Supabase** إن أردت حسابات حقيقية متعددة — بدونها يعمل التطبيق
> في الوضع المحلي فقط، وكل زائر يرى بيانات جهازه هو فقط.

### 4) تطبيق فيسبوك — تسجيل الدخول بفيسبوك (اختياري)
1. https://developers.facebook.com → My Apps → Create App → نوع **Consumer** → أضف منتج **Facebook Login**.
2. Settings → Basic: أضف `App Domains` = نطاق Vercel الخاص بك، وروابط الخصوصية وحذف البيانات (مطلوبة من Meta).
3. Facebook Login → Settings: أضف **Valid OAuth Redirect URI**:
   `https://YOUR-PROJECT-REF.supabase.co/auth/v1/callback`
4. في Supabase: Authentication → Providers → Facebook → الصق `App ID` و `App Secret` وفعّل.
5. اطلب **App Review** لصلاحية `email` إن أردت قراءة الإيميل لغير أدمن/مطوري التطبيق
   (`public_profile` متاحة افتراضيًا). **لا تطلب أي صلاحية مجموعات — أُلغيت في 2024.**

## 🧩 إضافة كروم «ناشر ميراكس» — النشر بضغطة واحدة (من حسابك أنت)

في مجلد [`extension/`](sandbox://workspace/novels-studio/extension/) إضافة Chrome (Manifest V3)
تنشر الفصل في الجروب من جلسة فيسبوك المسجّل دخول فيها المستخدم في متصفحه هو.

> **«النشر يتم بحسابك أنت» — شرط أساسي:** النشر باسم وحساب المستخدم الناشر نفسه
> فقط، وليس باسم/حساب محمود (الأدمن). الإضافة لا تملك أي توكن فيسبوك، ولا حسابًا
> مشتركًا، ولا تنشر بالنيابة عن الأدمن. تفتح تبويب الجروب وتملأ النص، **والمستخدم
> نفسه يضغط «نشر» داخل فيسبوك من حسابه هو**. التفاصيل والتحذيرات الكاملة في
> [`extension/README.md`](sandbox://workspace/novels-studio/extension/README.md).

- من صفحة الفصل: زر **«🚀 انشر عبر الإضافة (بحسابك أنت)»** يرسل النص المنسق
  (عنوان الرواية + رقم الفصل + النص + `#ميراكس_للروايات`) إلى الإضافة.
- إذا لم تكن الإضافة مثبتة، يشرح الزر التثبيت: `chrome://extensions` ← وضع المطوّر
  ← Load unpacked ← مجلد `extension/`.
- حماية: منشور واحد كل 60 ثانية على الأقل، وحالات واضحة (جاهز / جاري النشر /
  تم النشر / فشل).
- ⚠️ أتمتة عبر جلسة المتصفح — قد تخالف شروط فيسبوك أو تتوقف إذا غيّر فيسبوك
  واجهته، وقد تؤدي لتقييد الحساب عند الإفراط — استخدمها باعتدال وعلى مسؤولية المستخدم.
- ⚠️ **إضافة كروم نفسها لا تعمل على كروم أندرويد** — كروم الهاتف لا يدعم الإضافات أبدًا.
  **على أندرويد (موثق في [`extension/android/README.md`](sandbox://workspace/novels-studio/extension/android/README.md)):**
  (أ) **الموصى به: سكربت Tampermonkey** (`extension/android/novels-studio-publisher.user.js`)
  على **Firefox لأندرويد** — لا يحتاج توقيعًا ولا متجرًا؛
  (ب) **نسخة Firefox من الإضافة** (`extension/firefox/` — MV2) بعد توقيعها في AMO؛
  **Kiwi Browser متوقف منذ يناير 2025 وحُذف من Play — لا تستخدمه.**
- **النشر الفعلي في الجروب الحقيقي لم يُختبر أبدًا** (عمدًا — لن ننشر محتوى تجريبيًا
  في جروب فيه ~70,000 عضو). أول نشر حقيقي يجب أن يكون فصلًا حقيقيًا يراجعه كاتبه قبل الضغط على نشر.

## 🧪 التشغيل والاختبار محليًا

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # بناء الإنتاج — يجب أن ينجح بدون أخطاء
npm start
```

بدون متغيرات بيئة يعمل التطبيق في الوضع المحلي: أنشئ حسابين مختلفين من متصفحين/نوافذ خفية
وتأكد أن روايات ونقاط كل حساب منفصلة، وجرّب طلب التحقق ثم وافق عليه من حساب الأدمن.

## ✅ ما هو جاهز فعلًا، وما الذي يحتاج خطوة منك

| جاهز في الكود | يحتاج خطوة من المستخدم |
|---|---|
| حسابات متعددة (إيميل/كلمة مرور + فيسبوك عبر Supabase) | إنشاء مشروع Supabase + تشغيل ملف SQL + Bucket `covers` |
| فصل بيانات كل مستخدم (RLS في Postgres + طبقة محلية) | إضافة متغيرات البيئة في Vercel |
| طلب تحقق + لوحة أدمن للموافقة/الرفض | إنشاء تطبيق فيسبوك (لتسجيل الدخول بفيسبوك فقط) |
| محرر فصول، مكتبة، غلاف من الجهاز، PDF، نقاط، متصدرون | النشر على Vercel (زر Deploy أعلاه بعد رفع GitHub) |
| تجهيز منشور + رابط الجروب للنشر اليدوي | — |
| **غير ممكن إطلاقًا (حد من Meta):** تحقق تلقائي من العضوية، نشر آلي في الجروب | لا حل تقني رسمي — المسار اليدوي أعلاه هو البديل |

## 🔒 الأمان
- كلمات المرور تُدار عبر Supabase Auth (bcrypt) — لا تُخزَّن في الكود أبدًا.
- مفاتيح الخدمة في متغيرات بيئة سيرفر فقط. لا تضع أي سر في Git.
- RLS: كل مستخدم يصل لبياناته فقط؛ الأدمن يراجع طلبات العضوية فقط.
- لا ينشر التطبيق أي محتوى تجريبي في الجروب الحقيقي أبدًا.
